# ส่งต่องาน: flow จองรถ + ค่าจอง 1,000 บาท (Max-Branch)

อ่านไฟล์นี้ก่อนทำต่อ

## Flow ที่ต้องการ

1. ลูกค้าเลือกรถ วันที่ สาขา แล้วกดจอง
2. หน้าการจองขึ้นว่า **"รอผู้ดูแลยืนยัน"** ยังไม่มีสัญญา ยังไม่มี QR
3. แอดมินสร้างฉบับร่างสัญญา (ข้อมูลรถ + การจอง) แล้วกดส่งให้ลูกค้า
4. ลูกค้าอ่านฉบับร่าง แล้วเลือกได้ 2 ทาง
   - **ขอแก้ไข** ได้ 3 ช่อง: ชื่อลูกค้า, เวลารับรถ, เวลาคืนรถ (ต้องอยู่ช่วง 08:00–18:00)
     → แอดมินเห็นค่าเดิมเทียบค่าที่ขอ กดปุ่มเดียว ระบบสร้างฉบับใหม่และส่งกลับให้ลูกค้า
   - **ยืนยันสัญญา**
5. **กดยืนยันสัญญาแล้ว ต้องขึ้นหน้าชำระเงินทันที** (เลือก QR Code หรือบัตรเครดิต)
   - **ห้ามมีขั้น "รอผู้ดูแลอนุมัติ" อีกรอบ** ลูกค้ากดยืนยัน = อ่านสัญญาแล้ว
   - จ่ายค่าจอง **1,000 บาท** (ไม่ว่าจะเช่ากี่วัน) ภายใน **15 นาที** ไม่ทันการจองถูกยกเลิก
6. จ่ายแล้ว การจองเป็น "ยืนยันแล้ว"
7. **จ่ายยอดที่เหลือ** (ค่าเช่า + เงินประกัน − 1,000) ในหน้าการจองเดิม ด้วย QR หรือบัตรเหมือนค่าจอง จ่ายได้ตั้งแต่จ่ายค่าจองเสร็จจนถึงวันรับรถ ไม่มีจำกัด 15 นาที (`pay_pickup`)
8. คืนรถ ได้เงินประกันคืน (แสดงข้อความอย่างเดียว ไม่บันทึกการคืนเงิน)

### เงิน (ตัวอย่าง รถ 990 บาท/วัน × 3 วัน)

| รายการ                                            | ยอด   |
| ------------------------------------------------- | ----- |
| ค่าเช่า (ราคา/วัน × จำนวนวัน)                     | 2,970 |
| เงินประกัน (เท่ากับค่าเช่า)                       | 2,970 |
| ค่าจอง จ่ายออนไลน์หลังยืนยันสัญญา                 | 1,000 |
| จ่ายยอดที่เหลือออนไลน์ (ค่าเช่า + ประกัน − 1,000) | 4,940 |
| ได้คืนตอนคืนรถ (เงินประกัน)                       | 2,970 |

- ยกเลิกการจอง ไม่คืนค่าจอง
- ยอดที่เหลือบันทึกเป็นการชำระครั้งที่ 2 (`payments.kind = 'pickup'`, `payments.deposit` = เงินประกันในยอดนั้น) รายงานรายได้นับ `amount − deposit` จึงไม่นับเงินประกันเป็นรายได้
- การคืนเงินประกันตอนคืนรถ แค่แสดงข้อความ ไม่ได้บันทึกในระบบ
- ยกเลิกการจองที่จ่ายแล้ว การชำระทุกรายการถูกบันทึกว่า "ไม่คืนเงิน" (DEMO ไม่มีระบบคืนเงิน)

## สถานะตอนนี้

| ส่วน                                  | สถานะ                             |
| ------------------------------------- | --------------------------------- |
| หน้าเว็บ (โค้ดใน `Max-Branch`)        | เสร็จแล้ว เทสต์ผ่าน 270 ตัว       |
| ฐานข้อมูลจริง (Supabase ผ่าน Lovable) | **ยังไม่ได้อัปเดต** ← งานที่เหลือ |

ประวัติฐานข้อมูลวันที่ 14 พ.ย.: มีคนสั่ง Lovable รัน `0005_customer_self_accept_contract` (จองแล้วขึ้นสัญญาทันที ข้ามแอดมิน) แล้วรัน `0006_rollback_customer_self_accept_contract` ย้อนกลับ ตอนนี้ฐานข้อมูลจริงจึงกลับไปเป็นแบบ 0004 คือ

- จองแล้วรอแอดมิน (ถูก)
- **ลูกค้ากดยืนยันสัญญาแล้ว ยังขึ้น "รอผู้ดูแลอนุมัติ"** ต้องรอแอดมินกดอนุมัติอีกรอบถึงจะจ่ายได้ (ผิด)
- ตอนจ่ายเก็บ **ค่าเช่าเต็มจำนวน** ไม่ใช่ 1,000 และเงินประกันแอดมินกรอกเอง (ผิด)

หน้าเว็บใน `main` (หลัง merge `Max-Branch`) แสดงค่าจอง 1,000 และขึ้น QR หลังยืนยันแล้ว แต่ฐานข้อมูลยังไม่รองรับ จนกว่าจะรัน SQL ข้างล่าง

กฎเหล่านี้อยู่ในฐานข้อมูล แก้ในโค้ดหน้าเว็บอย่างเดียวไม่ได้ ต้องสั่งผ่าน Lovable

## งานที่เหลือ (ทำตามลำดับ)

1. **รัน SQL ใน Lovable** เปิดโปรเจกต์ drive-dee ใน Lovable พิมพ์ลงแชต:

   > Create a new database migration with exactly this SQL. Run it as-is. Do not change anything else:

   แล้ววางเนื้อหาทั้งหมดจาก [`docs/database/booking-fee-flow.sql`](database/booking-fee-flow.sql) ต่อท้าย กดอนุมัติ migration
   - Lovable อ่านได้แค่ branch `main` จึงต้องวาง SQL ทั้งก้อนลงแชต อ้างชื่อไฟล์ไม่ได้
   - SQL นี้: ปิดการสร้างสัญญาอัตโนมัติของ 0005 (ถ้ายังมี), ให้ยืนยันสัญญาแล้วไป `approved` ทันทีพร้อมเวลาจ่าย 15 นาที, `pay_booking` เก็บ 1,000, เงินประกัน = ค่าเช่า, เพิ่ม `pay_pickup` สำหรับยอดที่เหลือ
   - รายละเอียดและวิธีย้อนกลับ: [`docs/database/booking-fee-lovable-prompt.md`](database/booking-fee-lovable-prompt.md)

2. **เช็กว่ารันแล้ว** ในหน้าเว็บ (console ของเบราว์เซอร์ หรือโค้ด) เรียก `supabase.rpc("booking_fee")` ต้องได้ `1000`
3. **ทดสอบทั้ง flow** ตามหัวข้อ "Flow ที่ต้องการ" ข้างบน บัตรทดสอบ `4242 4242 4242 4242` ผ่าน, เลขลงท้าย `0002` ถูกปฏิเสธ
4. การจองเก่าที่มีสัญญาอยู่แล้ว ให้ยกเลิกแล้วจองใหม่
5. ผ่านแล้ว เปิด PR รวม `Max-Branch` เข้า `main`

**อย่า** สั่ง Lovable ให้รัน SQL เรื่อง flow สัญญาตัวอื่นเพิ่ม ไม่งั้นจะทับกันแบบ 0005/0006 อีก
